# Scaffold examples — clone, adapt, commit

Every file here is a **working template** for a new repo (generalized from
books_to_anki / chat-workflow / energy_envelope / houses / kilocode).
Copy the files you need into the new repo, then edit the `CHANGE` points.

Comment convention in every file:

- `CHANGE` — per-project values you MUST adjust (package name, ports, versions).
- `DO NOT CHANGE` — house invariants. Deviating is a smell the review bot
  will flag; if you think one is wrong for your repo, it's a standards
  discussion, not a local edit.

The rules these files implement are explained in `../SKILL.md` — the file
comments say *what* and *why*; the skill says *when* to deviate.
