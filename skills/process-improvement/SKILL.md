# Process Improvement

Classify process failures and route to the appropriate specialist.

## Process

### 1. Classify the Failure Domain

| If the issue involves... | Route to... |
|---|---|
| Process breakdowns, failures, recurring mistakes | Process Failure Analysis |
| Git/version control issues, branch violations | Git Workflow Management |
| Communication problems, disagreements, user corrections | Communication Protocol Management |
| Architecture or design pattern violations | Architecture Pattern Documentation |

### 2. Execute

Pass full context to the appropriate specialist. If the issue spans multiple domains, sequence them.

### 3. Document Where People Will Find It

Place improvements in the workflow context where the problem occurs, not in separate reference files:

- Playbook structure issues → Engagement Playbook DQS
- Component design violations → Business Component Creation Playbook
- DQS not catching violations → Specific DQS documents
- Session/entry point problems → PA Coordination Operations Playbook
- Git violations → Git Workflow Management component

## Key Principle

Don't bury process improvements in random documents. Put them where the mistake happens.
